# Full Q6 through the experimental cuDF API

The missing date support was in this prototype's FLOAT64-only API and buffer bindings. Meld already
had DATE support. The prototype now exposes it as `date32`: signed 32-bit days since 1970-01-01,
binding directly to Meld DATE on CPU and cuDF TIMESTAMP_DAYS on GPU. No additional Meld changes
were needed for dates.

This implements all predicates of [TPC-H Q6](https://tpc.org/tpc_documents_current_versions/pdf/tpc-h_v3.0.0.pdf)
with the validation parameters: shipping date in `[1994-01-01, 1995-01-01)`, discount in
`[0.05, 0.07]`, and quantity below 24. The output is `SUM(extendedprice * discount)`.
Numeric columns still use FLOAT64; decimal arithmetic and certified TPC-H benchmarking are outside
this prototype's scope.

## Build the graph

```cpp
#include <cudf/experimental/execution/cpu.hpp>

namespace ex = cudf::experimental::execution;
using ex::col;
using ex::lit;
using ex::date;
using T = ex::data_type;

// quantity, extendedprice, discount, shipdate
auto query = ex::input({T::float64, T::float64, T::float64, T::date32})
  .filter((col(3) >= lit(date(1994, 1, 1))) &&
          (col(3) < lit(date(1995, 1, 1))) &&
          (col(0) < lit(24)) &&
          (col(2) >= lit(0.05)) && (col(2) <= lit(0.07)))
  .project({col(1) * col(2)})
  .sum(col(0));

auto physical = ex::plan(query, {ex::target::cpu});
auto program = ex::compile_cpu(physical);
ex::host_table result = program.run(input_columns);
// Or: auto pending = program.submit(input_columns); auto result = pending.get();
```

`input_columns` contains four `host_column_view`s: three `double` spans and one `date32` span,
each with an optional validity bitmap. The schema is checked before execution. Dates are stored
as four-byte values throughout the JIT interface; mixed date/numeric comparisons are rejected.

The shared [query definition](tests/q6_workload.hpp) uses the equivalent original lazy API.
The [demo](tests/q6_demo.cpp) passes it to `ex::from_lazy()` so both APIs exercise the same graph.
The planner chooses one Meld fragment, `filter -> project -> sum`, with no materialized filter
or projection columns. Graph construction and compilation do not inspect or prefilter input data.

## Run it here

The current host build uses LLVM/MLIR 21.1.8, Arrow 21.0.0 and GCC 14.2 on Linux aarch64.
See [README.md](README.md) for a clean build on another host.

```bash
/tmp/jit-poc-sdk/bin/cmake --build /tmp/jit-poc-build -j2
/tmp/jit-poc-sdk/bin/ctest --test-dir /tmp/jit-poc-build --output-on-failure

# Synthetic rows, with shipping dates both inside and outside the window:
/tmp/jit-poc-build/q6_demo 1000000

# All rows from a 16-field, pipe-delimited DBGen-style lineitem file:
/tmp/jit-poc-build/q6_demo --lineitem /path/to/lineitem.tbl
```

The loader reads quantity, extendedprice, discount and shipdate from fields 5, 6, 7 and 11 of
`lineitem.tbl` (one-based). It accepts the optional trailing pipe. Loading and input generation
are outside the timings. Cold compilation is reported separately from the median of 20 warmed,
synchronous executions. Each execution uses one CPU thread. Results are checked against an
independent C++ reference; asynchronous submission is also checked.

## Independent SQL validation

The optional [validation script](tests/validate_q6_duckdb.py) generates data with DuckDB's
[tpch extension](https://duckdb.org/docs/2.0/core_extensions/tpch), runs the full Q6 SQL with
decimal numeric columns, exports lineitem, and compares the demo's result. It requires the
Python `duckdb` package and access to install the `tpch` extension; it is separate from CTest.

```bash
/tmp/jit-poc-sdk/bin/python cudf/cpp/examples/lazy_meld/tests/validate_q6_duckdb.py \
  /tmp/jit-poc-build/q6_demo --scale 0.01 --work-dir /tmp/jit-q6-validation
```

The October 29 run with DuckDB 2.0.0 generated **60,175 lineitem rows** at SF 0.01. DuckDB's
decimal result and the Meld FLOAT64 result both printed **1193053.2253**. The comparison uses
relative tolerance `1e-10` and absolute tolerance `1e-8`; this is not a claim of decimal-exact
arithmetic. DuckDB documents small differences between its generated data and the official TPC-H
specification. This is an independent query-correctness check, not an official benchmark result.
The [recorded output](results/q6-cpu-aarch64-2026-10-29.txt) includes commands and local timings.

Six host tests pass. The date fixture has a hand-calculated revenue of **37** and includes rows
whose numeric predicates pass but whose shipping dates fail. Tests cover the inclusive lower
and exclusive upper date boundary, discount bounds, quantity 24, null dates, all-excluded input,
calendar validation, signed day counts, sliced bitmaps, typed intermediate/output columns,
date grouping and asynchronous reuse. The compiler test also compiles full Q6 to PTX.

The GPU adapters and eager cuDF comparison tests now bind TIMESTAMP_DAYS and include the same
date predicates. They have **not been built or run on this CPU host**; follow the GPU validation
instructions in [README.md](README.md) and [EXPERIMENTAL_API.md](EXPERIMENTAL_API.md) after transfer.
